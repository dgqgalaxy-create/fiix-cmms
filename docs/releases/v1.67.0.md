# GTZ CMMS v1.67.0

Fecha: 30 de septiembre de 2026.

## Mejoras

- Personal interno: contador «Personal en turno ahora» y etiqueta de estado debajo del rol. Cuenta personas activas según Horarios, independientemente de filtros o conexión a la app.
- Hora de planta (Ciudad de México): día 07:00–19:00; noche 19:00–07:00 del día siguiente; mixto lunes a viernes 07:00–16:00 y sábado 07:00–12:00. Actualización cada minuto, al recuperar foco y al cambiar los horarios.
- Tiempo extra: entrada y salida configurables al asignar, incluidos tramos nocturnos.
- Tiempo por tiempo: deuda con fecha, horas y motivo; abonos en varias fechas con entrada/salida, historial y saldo. Quitar un abono restituye su saldo. Se rechazan abonos superiores al saldo y tramos superpuestos entre horas adicionales de la misma persona.
- Horarios: los selectores de asignación muestran únicamente personal activo. El servidor también rechaza nuevas asignaciones a personal inactivo; se mantiene el historial existente.
- Catálogo de solicitantes: búsqueda por nombre sin distinguir mayúsculas ni acentos, contador de resultados y mensaje sin coincidencias.
- Informe semanal: separación vertical entre los grupos de tres columnas de cada día.
- Consulta de Horarios: se corrigen los límites de fechas para incluir el primer día de campos DATE.

## Interpretación de los datos

El indicador representa la programación, no una verificación de asistencia. Los registros sin horario no se presumen descanso. TE/TxT sin horas no se cuentan como presencia actual fuera del turno regular. Los abonos registrados descuentan el saldo incluso si están programados para fechas futuras. Registrar una deuda no modifica automáticamente el turno de su fecha.

## Actualización del servidor

Esta versión requiere sincronizar el esquema de la base de datos antes de utilizar las funciones nuevas. Se agrega `TechnicianTimeDebt` y campos opcionales de horario y abonos a `TechnicianException`, conservando los datos existentes.

Se incluye la migración `20260930000000_roster_hours_and_time_debts`. En instalaciones que administran migraciones con Prisma, aplicar `npx prisma migrate deploy` desde backend. El flujo existente de este proyecto utiliza `update.sh`, que regenera Prisma y sincroniza el esquema con `prisma db push` sin permitir pérdida de datos por defecto. No mezclar ambos procedimientos para un mismo historial sin revisar su estado.

Un push a main activa el workflow de despliegue en el runner self-hosted. Confirmar el resultado en GitHub Actions antes de dar por actualizada producción. El punto de restauración estable continúa siendo `v1.66.0-stable`; esta entrega no lo reemplaza.

## Validación

- Compilación de frontend y backend.
- Pruebas de límites horarios, turnos nocturnos y mixtos, estados sin horas e incidencias.
- Pruebas de validación de entrada/salida, tres abonos de 3 h para una deuda de 9 h, exceso de saldo, superposición, titularidad, eliminación de abonos, fechas e inactivos.
- Revisión visual de tarjetas y formulario con datos ficticios.

Las pruebas de controladores utilizan persistencia simulada. No se aplicó el esquema ni se verificó el guardado contra una base real local, porque este entorno no tiene DATABASE_URL configurada.
